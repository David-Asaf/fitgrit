FitGrit product requirements document

⸻

1. introduction

This product requirements document (PRD) defines FitGrit, a cross‑platform mobile application focused on group fitness challenges. The document captures what we will build, for whom, and why, and provides the traceable requirements the engineering, design, and quality‑assurance teams need to deliver a minimum‑viable product (MVP) and its immediate follow‑ups.

⸻

2. product overview

Attribute	Description
Vision	Make group fitness challenges fun, inclusive, and effortless by turning every workout into a friendly competition.
Platforms	iOS & Android (React Native with Expo)
Back‑end	Supabase (PostgreSQL, auth, real‑time)
Monetisation	One‑time fee per challenge, tiered by participant capacity; no subscriptions
Core value	Seamless challenge creation and participation with automatic data sync from popular health sources (Apple Health, Google Fit, etc.)


⸻

3. goals and objectives

Time frame	Goal	Metric
MVP (0–3 mths)	Validate product/market fit with friend‑group & enthusiast segments	≥1,000 challenges created, ≥40 % 30‑day retention
6 months	Support corporate‑scale challenges and broaden device coverage	≤3 s leaderboard load for 1,000 users, Fitbit integration GA
12 months	Reach sustainable revenue via fee model	≥$50 k gross challenge fees, NPS ≥ 50

Secondary objectives:
	•	Foster organic growth via shareable results and public challenges
	•	Preserve user trust by exceeding platform privacy and security guidelines
	•	Build an extensible architecture for future gamification and AI coaching

⸻

4. target audience
	1.	Social exercisers – small friend groups seeking accountability
	2.	Data‑driven competitors – device‑savvy athletes hosting large events
	3.	Team builders – HR / community organisers running 100 + person challenges
	4.	Solo challengers – individuals joining public challenges for motivation

Primary launch focus: 1 and 2 for rapid feedback loops; requirements for 3 captured but scheduled post‑MVP.

⸻

5. features and requirements

5.1 functional requirements

Priority	Feature	Description
MVP	Account creation & secure login	Email/password, Sign in with Apple & Google, magic‑link
	Challenge creation (individual)	Select metric, duration, privacy, capacity; deep‑link invite
	Automatic data sync	Apple HealthKit, Google Fit / Health Connect
	Leaderboard	Real‑time ranking; pagination for >50 users
	Challenge chat	Group text thread with basic moderation
	Push notifications	Invite, start/end, status nudges
	One‑time fee payment	In‑app purchase for >free‑tier capacity
v1.1	Team challenges	Team aggregation & team leaderboard
	Additional integrations	Fitbit (high), Garmin (medium)
	Public challenge directory	Browse & join open challenges
	Enhanced analytics & badges	Milestones, shareable result cards
Future	Web admin dashboard, charity payouts, AI insights, marketplace	

5.2 non‑functional requirements
	•	Performance: Leaderboard initial load ≤ 3 s on 4G; background sync max every 15 min
	•	Reliability: 99.5 % uptime; queued retries for third‑party API failures
	•	Security & privacy: End‑to‑end TLS; OAuth tokens encrypted at rest; HIPAA‑grade data handling practices
	•	Scalability: Support a single challenge with 10 k participants and 1 M daily writes via aggregate tables and Supabase row‑level security
	•	Accessibility: WCAG 2.1 AA compliance; voice‑over labels for all graphs
	•	Compatibility: iOS 15+, Android 9+

6. user stories and acceptance criteria

ID	Title	User story	Acceptance criteria
ST‑101	Secure authentication	As a user, I want to sign up or log in quickly and securely so that I can access my challenges on any device.	1) Supports email + password, Apple, Google 2) Password reset via email link 3) JWT/session stored securely 4) 3 consecutive failed logins lock account for 5 min
ST‑102	Connect data source	As a user, I want to connect my preferred health data source so that my activity counts automatically.	1) App requests correct HealthKit / Fit scopes 2) Permissions screen explains usage 3) First sync pulls at least previous 24 h 4) User can revoke permissions in settings
ST‑103	Create challenge	As a user, I want to create an individual challenge with custom metric and dates so that my friends can join.	1) Creator selects metric (steps, distance, minutes, workouts) 2) Start date can be today or future 3) Duration presets + custom range (max 90 days) 4) Challenge saved and visible in dashboard
ST‑104	Invite participants	As a creator, I want to share a link or code so that others can join easily.	1) Unique, expiring deep link generated 2) Link opens app store if not installed, then auto‑routes to join screen 3) Joining after capacity full shows “challenge full” message
ST‑105	Join via link	As a new user, I want to join a challenge from a link with minimal setup so that I can start competing quickly.	1) After install, deep link persists through onboarding 2) User completes ST‑101 & ST‑102 then lands in challenge 3) User appears on leaderboard within 60 s of first sync
ST‑106	Leaderboard view	As a participant, I want to see an up‑to‑date leaderboard so I know my rank.	1) Shows top 50 and user’s own rank context 2) Pull‑to‑refresh triggers sync 3) Large challenges (>1 k) load additional pages on scroll
ST‑107	Challenge chat	As a participant, I want to chat with others in my challenge so we can motivate each other.	1) Messages delivered <300 ms on Wi‑Fi 2) Supports emoji reactions 3) Admin can delete messages; deleted message removed for all users
ST‑108	Event notifications	As a participant, I want timely notifications about key events so that I stay engaged.	Triggers: invite received, 24 h to start, challenge ended, rank change (max 3/day)
ST‑109	Pay challenge fee	As an organiser, I want to pay a one‑time fee for large challenges so that participants join free of hassle.	1) Tiered pricing shown before payment 2) In‑app purchase processed via App Store / Play Billing 3) On success, challenge status = Active; on failure, creation blocked
ST‑110	Data merge logic	As a system, I need to de‑duplicate overlapping data sources so participant totals are accurate.	1) User can set primary source in settings 2) Duplicate events identified by timestamp +/-5 s and type 3) No more than one record counted per metric per minute
ST‑111	Admin actions	As a challenge creator, I want to remove a participant violating rules so competition stays fair.	1) Remove option visible only to admin 2) Removed user receives notification 3) Leaderboard recalculates immediately
ST‑112	Manual entry fallback	As a participant without a tracker, I want to log steps manually so I can still compete.	1) Manual entry capped at 20 k steps/day 2) Entries flagged with “manual” icon 3) Admin audit report available
ST‑113	Database modelling	As an engineer, I need a schema that stores daily aggregates and raw workouts so that queries are performant and flexible.	1) Tables: users, challenges, membership, daily_metric, workouts_raw 2) PK/FK constraints enforce referential integrity 3) Composite index (challenge_id, metric_date) allows leaderboard query <500 ms for 10 k rows
ST‑114	Health data privacy	As a participant, I need assurance my health data is used only for challenges I join.	1) Privacy policy link in onboarding 2) Data retention: raw data purged 30 days post‑challenge 3) User can delete account and all data via settings
ST‑115	Challenge full edge case	As a user, I want clear feedback if a challenge is full so I’m not confused.	1) Attempt to join full challenge shows modal with wait‑list info 2) No fee charged 3) Analytics event recorded
ST‑116	Offline support	As a user with poor signal, I want the last synced leaderboard visible offline.	1) Cached leaderboard stored locally 2) “Offline – will sync when connected” banner displayed 3) Local cache expires after 24 h

7. technical requirements / stack

Layer	Technology	Notes
Mobile client	React Native (Expo SDK 50+)	EAS build & OTA updates
Auth	Supabase Auth	Email/password, OAuth, magic link
Database	Supabase PostgreSQL	Row‑level security, CDC for analytics
Realtime	Supabase Realtime channels	WebSockets for chat & leaderboard
Integrations	Apple HealthKit, Google Fit/Health Connect, Fitbit Web API	OAuth tokens stored encrypted
Payments	App Store / Google Play in‑app purchases (RevenueCat wrapper)	Stripe web checkout for corporate web admin (future)
DevOps	GitHub Actions → EAS build pipelines; Expo Updates for OTA	Sentry for crash reporting
Analytics	PostHog (self‑hosted on Supabase)	Tracks funnel, retention, feature usage
Notifications	Expo Push + FCM/APNS	Topic‑based subscription per challenge
Security	AES‑256 at rest, TLS 1.3 in transit, OWASP MASVS guidelines	3rd‑party penetration test before GA

8. design and user interface

8.1 principles
	•	Challenge first: home screen surfaces current and upcoming challenges; no generic activity feed.
	•	One‑hand simplicity: primary actions reachable within bottom‑tab bar; creation wizard ≤ 4 steps.
	•	Inclusive visuals: vibrant colour palette compliant with WCAG contrast; avatar placeholders for anonymity.
	•	Gamified feedback: confetti animation on milestone unlock; badge shelf on profile.

8.2 key screens

Screen	Purpose	Primary elements
Home	Overview & navigation	Active challenges list, create button, profile icon
Create challenge wizard	Step‑by‑step setup	Metric selector → duration → capacity/pricing → invite share sheet
Challenge dashboard	Core interaction hub	Header (name, countdown), leaderboard, chat tab, invite button
Leaderboard	Competitive view	Top 3 podium, list with infinite scroll, pull‑to‑refresh
Chat	Social glue	Threaded messages, emoji reactions, admin delete
Profile	Identity & settings	Avatar, badges grid, connected devices, privacy & data controls

Low‑fidelity wireframes are attached separately in Figma (link TBD) and will progress to high‑fidelity during sprint 2.
